The problem

A missed sentence can mean a missed idea.

Following a lecture in a second language takes more than knowing individual words. A student may still be making sense of one sentence when the speaker moves on to the next.

We built Classroom Live to give students another way to follow the discussion: read the English as it is recognized, consult a translation, and return to the transcript after class. The same workflow supports reviewing recorded audio and video.

The aim is useful learning support. Recognition and translation can make mistakes, so the original English remains visible alongside the model’s output.

How it works

One voice. Two stages of understanding.

Speech recognition and translation run separately, so English can appear while the language model is still working.

    Capture speech

    The browser requests microphone permission and sends audio to the app running on the laptop.

    Browser audio + speech detection
  2. 02

    Show the English

    Whisper recognizes spoken English. The first transcript appears immediately after recognition.

    faster-whisper · base.en
  3. 03

    Correct and translate

    A local language model corrects the text and translates it into the selected language.

    Ollama · Qwen2.5 3B
  4. 04

    Read and save

    The transcript updates with the translation. Original English stays available, and results can be exported.

    Browser display + text export

For recordings: FFmpeg prepares the audio before recognition. Students can choose transcription alone or add correction and translation.

Engineering decisions

The choices behind the experience.

We balanced accessibility, privacy, and useful feedback against the limits of laptop hardware.

01 / Responsiveness

Let English arrive before the translation.

Waiting for every model to finish made the app feel slow. Separate workers now publish English first and add the correction and translation afterward. This gives students earlier feedback, although the final bilingual result still takes longer.

02 / Local processing

Keep speech processing on the student’s laptop.

Whisper and Ollama run locally, without a cloud API key or per-use API fees. The trade-off is computing demand: model files take space, and translation speed varies with the laptop. The image and initial model downloads require internet access.

03 / Installation

Package the whole runtime in Docker.

Installing Python, FFmpeg, and a language-model service separately is a lot to ask of a first-time user. Our image includes those components. A student pulls it in Docker Desktop, maps a port, and opens the app in a browser. Docker installation and microphone permissions remain necessary.

04 / Browser audio

Capture the microphone where the student is.

The app already had a web interface, but its original audio capture used the server computer’s microphone. For Docker, we added browser capture and streamed audio into the existing speech pipeline. AI-assisted development helped implement the change; protocol tests and real-model checks were used to verify it.

English first

A useful response to waiting

Earlier Surface Pro 9 observations estimated 2–3 seconds to English and 7–8 seconds to corrected translation. Showing English sooner improved responsiveness without proving faster translation.

Informal observations; results depend on hardware and input.

What we would improve next

Preserve context across sentence boundaries, reduce translation delays, and evaluate accuracy in realistic classroom noise. Generated corrections can change meaning, so the interface retains the original transcription for comparison.
